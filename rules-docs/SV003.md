# SV003: SavedVariables defaults without a schema version

**Category:** savedvars

## Why

With more than a handful of nested settings, the next release will rename or restructure a key. Without a `schemaVersion`/`version` field in the saved table there is no reliable way to know which layout a player's file has, so migrations guess (and often wipe). Reported once per addon when the defaults/SV keys reach six and no key containing `version`/`schema` exists. Addons using AceDB-3.0 are skipped.

## Bad

```lua
local addonName = ...
local defaults = {
  enabled = true,
  scale = 1,
  frame = { x = 0, y = 0, point = "CENTER" },
  colors = { r = 1, g = 1, b = 1 },
}
local f = CreateFrame("Frame")
f:RegisterEvent("ADDON_LOADED")
f:SetScript("OnEvent", function(self, event, loaded)
  if loaded ~= addonName then return end
  MyAddonDB = MyAddonDB or CopyTable(defaults)
end)
```

## Good

```lua
local addonName = ...
local SCHEMA = 2
local defaults = {
  schemaVersion = SCHEMA,
  enabled = true,
  scale = 1,
  frame = { x = 0, y = 0, point = "CENTER" },
  colors = { r = 1, g = 1, b = 1 },
}
local f = CreateFrame("Frame")
f:RegisterEvent("ADDON_LOADED")
f:SetScript("OnEvent", function(self, event, loaded)
  if loaded ~= addonName then return end
  MyAddonDB = MyAddonDB or CopyTable(defaults)
  if (MyAddonDB.schemaVersion or 1) < SCHEMA then
    MyAddonDB.colors = MyAddonDB.colors or {}
    MyAddonDB.schemaVersion = SCHEMA
  end
end)
```
