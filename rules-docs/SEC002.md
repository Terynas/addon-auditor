# SEC002: Replacing a Blizzard function or global

**Category:** security

## Why

Assigning over a client API or FrameXML function (`SetItemRef = ...`, `_G.ChatFrame_OnEvent = ...`, `function GameTooltip:SetUnit() ... end`) replaces it for the default UI and every addon. Secure Blizzard code that calls it now runs tainted addon code, which surfaces later as `ADDON_ACTION_BLOCKED` / "Interface action failed because of an AddOn" far from the real cause. `hooksecurefunc` runs your code after the original without replacing it. Polyfills guarded by `if not X then` or `X = X or ...` are not reported. Overlaps luacheck W121/W122 (LINT004); this finding wins the dedupe.

## Bad

```lua
local origSetItemRef = SetItemRef
SetItemRef = function(link, text, button, chatFrame)
  if link:find("^myaddon:") then return end
  return origSetItemRef(link, text, button, chatFrame)
end
```

## Good

```lua
hooksecurefunc("SetItemRef", function(link)
  if link:find("^myaddon:") then print("MyAddon link clicked") end
end)
```
